# UI/UX 设计原则（草案）—— UI 重做时的输入

* 版本：草案 v0.2（非现状文档，不进 DESIGN.md 的契约）
* 日期：2026-09-13（v0.2 事实核查修订：补 Cowan 2001、修正张小龙与 Material 3 引用、标注无埋点数据风险、补开工前置条件）
* 用途：UI 正式设计开工前，作为设计输入和自查清单。开工后本文件并入设计稿。

## 一、三条原则（已定，UI 设计的最高约束）

1. **禁止功能倾倒。** 把筛选、理解、决策的认知成本转嫁给用户，本质是开发者的懒惰。
   自查问题：这个入口用户一周用几次？不放主界面用户找得到吗？
2. **渐进式呈现（Progressive Disclosure）。** 日常路径上只留一把最锋利的刀；高级功能收进抽屉，在情境出现或用户主动探索时才滑出。
   代价须知：藏起来的功能被发现率低——NN/g 2016 隐藏导航研究（Pernice & Budiu）发现主导航藏进汉堡菜单后可发现性近乎减半。所以「藏什么」用使用频率 × 出错代价决定，且抽屉入口必须可被猜到。
3. **情境触发引导，拒绝全屏教程蒙版。** 在用户第一次悬停、第一次空状态、第一次遇到分支时，在视线停留处递一句人话。
   纪律：提示必须可关闭且不重复出现；能靠 UI 自解释（意符）就不引导。

## 二、本项目落地对照（现状自查，UI 重做时逐条处理）

* **已做对**：聊天是默认落地 tab——但经 2026-09-13 代码核实，「唯一主入口」是误述：底部导航把工具箱放成了与聊天平级的入口，这把刀目前并不孤独。错误信息是情境内的人话（红色气泡；401/未配置带下一步动作，429/超轮数等暂无）；AI 工具参数用智能默认值，不问用户。（注意：这是开发者自评，无用户证据，重做时先当假设看。）
* **待改（部分已裁决）**：工具箱 10 张卡平铺 = mini 功能倾倒。已裁决并落地的是双模式：「自己直接用」+「让 AI 执行」——2026-09-13 起卡片点按改为打开直接操作页（表单按 ToolDef 自动生成），页内保留「让 AI 来」兜底，AI 路径同时保留在聊天入口。剩余待裁决：目录形态——主界面只留聊天、工具箱降级为抽屉，还是按场景分组；工具变多后此问题会更痛。
* **已落地（2026-09-13）**：空状态即首次引导——原描述「空状态只有一行灰字」经代码核实不准确，当时空状态是什么都没有；现已改为一句人话 + 3 个真实工具的示例入口（点按填草稿不代发，发出首条消息后自然消失）。二维码卡片就地出现「保存到相册 / 分享」，反馈留在卡片内。
* **数据缺口**：「使用频率 × 出错代价」需要埋点数据，当前没有。重做前先补最小埋点，或把频率标成（估）并在设计稿里显式列出假设——别让自估伪装成事实。

## 三、资料清单（按层读，不必全读）

底层论文（给规律，读摘要即可）：

* Miller (1956) The Magical Number Seven, Plus or Minus Two —— 历史起点；但 7±2 说的是绝对判断与允许组块的记忆广度，经典误用是套到菜单项数
* Cowan (2001) The Magical Number 4 —— 现代修正：工作记忆真实容量约 4±1（Behavioral and Brain Sciences 24(1)），读这篇比 Miller 更要紧
* Hick (1952) / Fitts (1954) —— 选择越多决策越慢（对数关系，且分类良好的菜单会衰减）；目标越大越近越快点到
* Sweller (1988) Cognitive Load Theory —— 核心是降低外在认知负荷（教学设计语境）；套到产品 UI 是类比而非直接证据，「少即是多」更直接的依据是 NN/g 第 8 条和隐藏导航研究

正典书（选两本精读即可，推荐 Norman + Krug）：

* Don Norman《设计心理学》（The Design of Everyday Things）—— 示能 / 意符 / 反馈 / 映射
* Steve Krug《Don't Make Me Think》—— 别让用户思考；删掉一半字，再把剩下的一半删掉
* Alan Cooper《About Face》—— 目标导向设计：先问用户要完成什么，再谈功能
* Garrett《用户体验要素》—— 战略/范围/结构/框架/表现五层，和本项目分层文档同构

平台规范（做 Android 必读，权威且免费）：

* Material Design 3：Onboarding 模式 —— 官方三种模式（Self-select / Quickstart / Top user benefits），其中 Top user benefits 本身就是 ≤3 页可跳过轮播——官方不是「反对轮播」，是约束轮播；与本文原则 3 同向的是 Quickstart 的情境内高亮
* Apple HIG：Onboarding 与 Empty States 章节（观点通用，别局限于 iOS）

专题文章：

* NN/g《10 Usability Heuristics》（第 8 条 Aesthetic and Minimalist Design 就是反功能倾倒）
* NN/g《Progressive Disclosure》（Nielsen, 两篇）—— 渐进式呈现的原始出处与适用条件
* NN/g《Hamburger Menus and Hidden Navigation Hurt UX Metrics》（Pernice & Budiu, 2016）—— 「藏起来发现率低」的实据，导航场景，外推到抽屉需自行拿捏

中文语境：

* 张小龙两个文本别混引：《微信背后的产品观》是 2012 年前后流传的内部 8 小时演讲；2019 微信公开课是另一场 4 小时公开演讲（微信之夜，回顾微信 8 年）。「自然」的设计、用完即走，中文产品哲学最好的公开表述

## 四、开工时的流程裁决（防止研究变拖延）

开工前置：本草案所在目录目前只有本文档（无代码、无 DESIGN.md）；正式开工前先定位代码库、把本文件转正进 DESIGN.md，否则第二节的「现状自查」无从对照。

读资料上限：正典书两本 + Material 3 对应章节 + NN/g 两篇专题，两周内读完即开工。
验证方式：可丢弃原型（Figma 或直接 Compose 摆两版）找人点一遍，比继续读书快。（前提：有可运行的构建和愿意点的人，两者目前都没落实。）
